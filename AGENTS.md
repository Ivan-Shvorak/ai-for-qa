# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in this repository.

## Overview

Teaching project for a lecture on using AI tools (Claude and Claude Code) in manual and automated QA. It holds the lecture slides plus live demos that students can repeat: the same QA tasks solved by different models (Opus, Sonnet, Haiku), and project skills that turn requirements into a checklist and a checklist into Playwright tests.

Demo targets are public practice sites, not our own product:

- **Juice Shop registration** — https://jshop.mate.academy/#/register (manual testing demo)
- **demoqa Student Registration form** — https://demoqa.com/automation-practice-form (automation demo)

Never register real people, use real personal data, or run load against these sites. Use generated test data only.

## Structure

```

  checklist-task-requirements.md  Requirements JS-REQ-001..010 for the registration form
  checklists/                     Output of the qa-checklist skill
automation-testing-opus/        Same Playwright task solved by Opus  (JavaScript, CommonJS)
automation-testing-sonnet/      ... by Sonnet
automation-testing-haiku/       ... by Haiku
.claude/skills/                 Project skills (see below)
.claude/new-feature-to-test/    Feature briefs for playwright-write-tests-for-new-feature
```

The `automation-testing-*` folders are a side-by-side model comparison. Keep each one self-contained: don't copy code between them, and don't "fix" one model's output with another's — the differences are the point of the demo.

## Skills (the QA workflow)

| Skill | Input | Output |
|---|---|---|
| `qa-checklist` | Requirements file or pasted acceptance criteria | `manual-testing/checklists/<feature>.md` |
| `playwright-write-tests-for-new-feature` | Feature brief or a checklist from `qa-checklist` | Page object + spec in the target `automation-testing-*` folder, run 3× green |

Typical demo flow: requirements → `qa-checklist` → review the checklist by hand → `playwright-write-tests-for-new-feature` → review the diff and the test run.

## Commands

Run from inside an `automation-testing-*` folder:

```bash
npm install && npx playwright install chromium   # first-time setup
npm test                                         # all tests, headless Chromium
npx playwright test tests/<file>.spec.js         # single file
npx playwright test -g "<test title>"            # single test by title
npx playwright test --headed                     # watch the browser
npx playwright test --repeat-each=3 --retries=0  # flakiness check
npx playwright show-report                       # HTML report
npx playwright show-trace test-results/<dir>/trace.zip   # debug a failure
```

There is no lint or build step. The Playwright MCP server is used to explore pages before writing tests.

## Conventions

- Playwright tests are **JavaScript (CommonJS)**, `require('@playwright/test')`.
- Locators: roles and visible text first (`getByRole`, `getByLabel`, `getByText`); `#id`/CSS only when nothing better exists.
- Page objects in `pages/`, test data in `test-data/`, specs in `tests/`. Page-ready method is named `openAndAssert`.
- Never use `page.waitForTimeout`; wait for elements, URLs or responses.
- Never weaken an assertion to make a test pass. If the site violates a requirement, it's a bug: mark the test `test.fail()` and report it.
- Checklists: one line per case, "User can / User can NOT ...", ending with the requirement ID (e.g. `(JS-REQ-003)`).

## Site quirks (learned the hard way)

### demoqa

- **Ads overlap elements** (for example the Submit button). Block them with `page.route(/googlesyndication|doubleclick|adplus|googletagservices/, r => r.abort())` before `goto`.
- **react-select fields** (`#subjectsInput`, `#react-select-3-input` for State, `#react-select-4-input` for City):
  - `fill()` does not open the menu. Click the input, then `pressSequentially()`.
  - Choose with `getByRole('option', { name, exact: true }).click()`.
  - Do **not** press `Enter` to select: if the menu hasn't rendered yet, Enter submits the whole form.
- **The date picker** (`#dateOfBirthInput`) keeps focus after a day is picked. Click the next field explicitly before typing into it.
  - Select days with `.react-datepicker__day--0DD:not(.react-datepicker__day--outside-month)`.
  - The confirmation modal formats the date as `15 May,1990`.
- **Gender and hobby inputs** are hidden behind their labels. Click the `<label>`, not the `<input>`.
